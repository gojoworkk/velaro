# Velaro — бэкенд, этап 1: ядро (приём заявок + Telegram)

Дата: 2026-10-15. Статус: дизайн утверждён, ждёт ревью спецификации.

## Контекст

Лендинг Velaro (аренда премиальных авто) — статические `index.html`, `styles.css`, `script.js`.
Форма заявки сейчас никуда не отправляется: после проверки полей показывается «Заявка отправлена»,
машины и цены зашиты в `script.js`.

Бэкенд делится на 4 этапа, у каждого своя спецификация и план:

1. **Ядро** (этот документ): сервер, база, приём заявок, уведомление в Telegram.
2. Админка заявок: вход нескольких менеджеров по логину и паролю, статусы, комментарии, повторная отправка в Telegram.
3. Автопарк и цены из админки: лендинг берёт машины и цены с сервера, фото загружаются в хранилище.
4. Занятость машин по датам: календарь броней, занятые даты нельзя выбрать.

## Решения

| Вопрос | Решение |
|---|---|
| Хостинг | Vercel; код на GitHub, деплой из репозитория |
| Стек | Next.js (App Router) + TypeScript; лендинг лежит в `public/` без изменений |
| База | Neon Postgres через Vercel Marketplace, ORM Drizzle, миграции файлами |
| Уведомления | Telegram-бот @velaro6782bot, сообщение в чат менеджера |
| Админка (этап 2) | несколько менеджеров, у каждого свой логин |

**Риск 152-ФЗ.** Персональные данные граждан РФ (имя, телефон) при сборе должны записываться в базу
на территории РФ. Neon работает за рубежом. Решение владельца: стартуем на Neon, перед запуском
с реальными клиентами переносим базу в российское облако (например, Yandex Managed PostgreSQL).
Поэтому используется только стандартный Postgres без специфичных возможностей Neon —
перенос сводится к смене `DATABASE_URL` и прогону миграций.

## Структура проекта

```
public/              лендинг: index.html, styles.css, script.js (как сейчас)
app/api/requests/route.ts   POST — приём заявки
lib/db.ts            подключение к Postgres (Drizzle)
lib/pricing.ts       сутки, скидка за срок, итог
lib/validation.ts    проверка полей заявки
lib/telegram.ts      отправка уведомления
lib/rate-limit.ts    лимит заявок по IP
db/schema.ts         таблицы
db/seed.ts           9 машин из текущего каталога
drizzle/             файлы миграций
tests/               Vitest
```

Главная страница `/` отдаёт `public/index.html` (rewrite в `next.config`). Адреса и вид лендинга не меняются.

## Данные

### `cars`
`id` (text, PK: `gt3rs`, `ferrari-roma`, …), `name`, `category` (`sport` | `suv` | `business`),
`power_hp`, `accel_0_100` (text, «3,3»), `seats`, `price_per_day` (int, ₽), `deposit` (int, ₽),
`active` (bool, default true), `sort_order` (int).

Заполняется сидом из текущего `CARS` в `script.js`. На этапе 1 лендинг продолжает показывать свои цены;
сервер считает стоимость по таблице `cars`. Дублирование убирается на этапе 3.

### `requests`
`id` (serial — номер заявки), `created_at`, `name`, `phone` (`+7XXXXXXXXXX`), `car_id` → `cars.id`,
`date_from`, `date_to` (date), `delivery` (`delivery` | `pickup`), `address` (nullable),
`comment` (nullable), `days`, `day_rate`, `total`, `deposit` (int, зафиксированы на момент заявки),
`status` (text, default `new`), `telegram_sent` (bool, default false).

### `rate_limits`
`ip_hash` (text), `created_at`. Хранится только SHA-256 от IP с секретной солью, записи старше
суток удаляются при очередной вставке. Сам IP не сохраняется.

### Скидки за срок
Константы в `lib/pricing.ts`: 1–2 суток — 0%, 3–6 — 10%, 7–13 — 20%, от 14 — 30%.
Цена за сутки округляется до 100 ₽ — как в текущем `dayRate` лендинга, чтобы суммы совпадали.
Сутки: разница дат, минимум 1 (в один день — 1 сутки).

## Поток заявки

1. Лендинг проверяет поля как сейчас и отправляет JSON на `POST /api/requests`:
   `{ name, phone, carId, dateFrom, dateTo, delivery, address?, comment?, website }`
   (`website` — невидимое поле-ловушка).
2. Сервер:
   - ловушка заполнена → ответ 200 с фиктивным успехом, в базу ничего не пишется;
   - лимит: больше 5 заявок с одного IP за 10 минут → 429;
   - валидация (zod): имя 1–100 символов; телефон → 11 цифр, нормализация в `+7…`;
     машина существует и `active`; `dateFrom` ≥ сегодня (Москва, UTC+3); `dateTo` ≥ `dateFrom`;
     при `delivery` адрес обязателен; комментарий ≤ 1000 символов → 400 с ошибками по полям;
   - пересчёт стоимости по `cars.price_per_day` и скидкам;
   - вставка в `requests`;
   - отправка в Telegram; при успехе `telegram_sent = true`.
3. Ответ `201 { id }`. Лендинг показывает «Заявка №{id} отправлена…».

Формат сообщения в Telegram (HTML-разметка, данные экранируются):

```
🚗 Новая заявка №17
Lamborghini Huracán EVO · 20–27 октября (7 суток)
120 000 ₽/сутки · итого 840 000 ₽ · депозит 300 000 ₽
Анна, +7 999 123-45-67
Доставка: Тверская, 1
Комментарий: …
```

## Ошибки

| Ситуация | Сервер | Лендинг |
|---|---|---|
| Неверные поля | 400 `{ errors: { field: message } }` | подсвечивает поля как сейчас |
| Лимит | 429 | «Слишком много заявок подряд. Позвоните нам: +7 495 000-00-00» |
| Telegram недоступен | заявка сохранена, `telegram_sent = false`, 201 | обычный успех |
| База недоступна / 500 | 500 | «Не получилось отправить. Позвоните нам…», данные формы не стираются |

## Секреты

Переменные окружения (Vercel → Settings → Environment Variables; локально `.env.local`, в git не попадает):
`DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `IP_HASH_SALT`.

## Тестирование

Vitest:
- `pricing`: границы скидок 1/2/3/6/7/13/14 суток, одна дата, даты в разных месяцах, округление.
- `validation`: каждое правило по отдельности, нормализация телефона.
- `POST /api/requests` на PGlite (Postgres в памяти) с заглушкой Telegram: сохранение, пересчёт цены
  (цена из запроса игнорируется), ловушка, лимит 429, сбой Telegram → 201 и `telegram_sent = false`,
  неактивная машина → 400.

Ручная проверка: локальный сервер + форма в браузере → заявка в базе Neon и сообщение в Telegram;
затем то же на деплое Vercel.

## Вне этого этапа

Админка и вход менеджеров, редактирование машин и цен, загрузка фото, календарь занятости,
перенос базы в РФ, оплата онлайн.
