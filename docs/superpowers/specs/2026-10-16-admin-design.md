# Velaro — бэкенд, этап 2: админка заявок

Дата: 2026-10-16. Статус: дизайн утверждён, ждёт ревью спецификации.

## Контекст

Этап 1 готов и работает на https://velaro-three.vercel.app: форма лендинга шлёт заявку в
`POST /api/requests`, сервер считает цену по тарифу из базы, сохраняет заявку в Neon Postgres
и отправляет сообщение в Telegram (@velaro6782bot). Смотреть и вести заявки сейчас негде,
кроме Telegram.

Этот этап добавляет закрытую админку `/admin` для владельца и нескольких менеджеров.
Этапы 3 (автопарк и цены из админки) и 4 (календарь занятости) — отдельные спецификации;
они будут встраиваться в эту админку.

## Решения

| Вопрос | Решение |
|---|---|
| Вход | логин + пароль, аккаунты создаёт владелец; регистрации нет |
| Реализация входа | своя: таблицы `users` и `sessions` в нашей базе, пароли — `scrypt` из `node:crypto`, без внешних сервисов и библиотек |
| Роли | `owner` (владелец) и `manager`; менеджер видит и ведёт все заявки, владелец ещё управляет менеджерами |
| Связь с Telegram | в уведомление о заявке добавляется ссылка на её карточку в админке |
| Дизайн | как у лендинга: Archivo для крупных заголовков, Inter для текста, белый фон, панели и бейджи `#141414`, скругления 16/24 px, белые и чёрные «пилюли» |

Не входит в этап: восстановление пароля по почте (пароль сбрасывает владелец), двухфакторный вход,
статистика, экспорт в Excel, кнопки действий внутри Telegram.

## Страницы

Все страницы рендерятся на сервере (Next.js App Router). Лендинг в `public/` не меняется.

### `/admin/login` — вход
- Чёрный экран как первый экран лендинга: надпись VELARO, поля «Логин», «Пароль», белая пилюля «Войти».
- Ошибка всегда одна: «Неверный логин или пароль» — не выдаём, существует ли логин.
- Защита от подбора: после 5 неудачных попыток за 15 минут для пары «логин + IP» —
  «Слишком много попыток. Попробуйте через 15 минут.»
- Параметр `?next=/admin/...` — после входа возвращает туда (только пути внутри `/admin`).
- Если у пользователя стоит флаг «сменить пароль», после входа он попадает на `/admin/password`.

### `/admin/password` — смена пароля
- Поля «Новый пароль» и «Повторите». Минимум 8 символов.
- Обязательна при первом входе и после сброса пароля владельцем. Доступна и вручную из шапки.
- После смены все остальные сессии пользователя удаляются.

### `/admin` — список заявок
- Шапка: VELARO слева; справа пилюли «Заявки», «Менеджеры» (только владельцу), имя пользователя, «Выйти».
- Вкладки со счётчиками: Новые · В работе · Подтверждены · Завершены · Отменены · Все. По умолчанию — «Новые».
- Поиск по имени и телефону (в телефоне учитываются только цифры), фильтр по машине.
- Строка заявки: №, когда создана, клиент + телефон, машина, даты аренды, итог, статус (чёрный бейдж), ответственный.
- Заявки без ответственного выделены. Сортировка — новые сверху. По 50 на страницу, кнопки «Назад/Дальше».
- На ширине < 768 px строки становятся карточками.
- Фильтры живут в адресе (`?status=new&q=...&car=...&page=2`), чтобы ссылкой можно было поделиться.

### `/admin/requests/[id]` — карточка заявки
- Клиент: имя; телефон ссылкой `tel:`, рядом ссылки «WhatsApp» (`https://wa.me/7...`) и «Telegram» (`https://t.me/+7...`).
- Аренда: машина, даты, суток, цена за сутки, итог, депозит; доставка с адресом или самовывоз; комментарий клиента.
- Ответственный и кнопки:
  - «Взять в работу» — если ответственного нет;
  - «Передать» — выпадающий список активных пользователей; доступно ответственному и владельцу.
- Смена статуса — пилюли статусов, текущий выделен. Переход возможен в любой статус.
- Заметки: поле ввода (до 2000 символов) и лента заметок с автором и временем.
- История: «Анна взяла в работу», «Иван: В работе → Подтверждена», «Иван передал Анне» — с временем.
- Если уведомление не ушло в Telegram (`telegram_sent = false`), пометка «Не отправлено в Telegram» и кнопка «Отправить ещё раз».
- Несуществующий номер — страница «Заявка не найдена» со ссылкой «К списку заявок».

### `/admin/managers` — менеджеры (только владелец)
- Таблица: имя, логин, роль, активен, последний вход.
- «Добавить менеджера»: имя, логин (латиница, цифры, точка, дефис, подчёркивание; 3–32 символа; уникальный), временный пароль (от 8 символов).
  Новый аккаунт получает флаг «сменить пароль».
- «Сбросить пароль»: владелец задаёт новый временный пароль; ставится флаг «сменить пароль», все сессии менеджера удаляются.
- «Отключить» / «Включить». Отключение удаляет все сессии — менеджер вылетает при следующем действии.
- Владельца нельзя отключить, понизить или удалить. Удаления аккаунтов нет — только отключение,
  чтобы в истории заявок сохранялись авторы.

### Изменения `requests`
- Новое поле `assigned_to` — integer FK → users, null.
- `status` остаётся text; допустимые значения проверяются в коде:
  `new`, `in_progress`, `confirmed`, `completed`, `cancelled`.

### Статусы
`new → in_progress → confirmed → completed`, из любого — `cancelled`. Переходы свободные (можно вернуть назад),
каждое изменение пишется в `request_events`. «Взять в работу» назначает ответственного и, если статус `new`,
ставит `in_progress` — две записи в истории.

### Первый владелец
Скрипт `npm run admin:create-owner` спрашивает в терминале логин, имя и пароль (ввод пароля скрыт)
и создаёт пользователя `owner` с `must_change_password = false`. Если владелец уже есть — отказывается.
Пароль в чат и в файлы не попадает.

## Устройство

```
app/admin/layout.tsx              шрифты, admin.css
app/admin/login/page.tsx          вход (без проверки сессии)
app/admin/(app)/layout.tsx        проверка сессии, шапка; must_change_password → /admin/password
app/admin/(app)/page.tsx          список заявок
app/admin/(app)/requests/[id]/page.tsx
app/admin/(app)/managers/page.tsx только owner, иначе 404
app/admin/password/page.tsx
app/admin/actions.ts              серверные функции (вход, выход, действия с заявками и менеджерами)
app/admin/admin.css               стили на переменных лендинга
lib/auth/password.ts              hashPassword / verifyPassword (scrypt, сравнение timingSafeEqual)
lib/auth/session.ts               createSession / getSessionUser / deleteSession / deleteUserSessions
lib/auth/login.ts                 login(): блокировка попыток + проверка пароля + сессия
lib/auth/guard.ts                 requireUser(role?) для страниц и действий
lib/admin/requests.ts             listRequests, getRequest, takeRequest, assignRequest, setStatus, addNote, resendTelegram
lib/admin/users.ts                createManager, resetPassword, setActive, changeOwnPassword
scripts/create-owner.ts
```

- Логика в `lib/` принимает `db` параметром (как `createRequest` в этапе 1) и тестируется на PGlite.
  Страницы и `actions.ts` только читают форму, вызывают `lib/` и делают `redirect`/`revalidatePath`.
- **Проверка прав на сервере в каждой серверной функции**, не только скрытием кнопок:
  `requireUser()` для любых действий, `requireUser('owner')` для менеджеров.
- Cookie `velaro_session`: `HttpOnly`, `Secure` (в продакшене), `SameSite=Lax`, `Path=/admin`, 30 дней.
  Серверные функции Next.js дополнительно сверяют Origin — защита от CSRF.
- Все страницы `/admin` — `dynamic`, без кэша; заголовок `X-Robots-Tag: noindex`.
- «Взять в работу» — один условный `UPDATE ... WHERE id = ? AND assigned_to IS NULL RETURNING`:
  при одновременных нажатиях выигрывает первый, второй получает «Заявку уже взял(а) <имя>».

### Telegram
В конец сообщения о новой заявке добавляется строка со ссылкой `<SITE_URL>/admin/requests/<id>` («Открыть в админке»).
`SITE_URL` — новая переменная окружения (`https://velaro-three.vercel.app`, после покупки домена — новый адрес).
Без `SITE_URL` ссылка не добавляется, остальное работает как раньше.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Нет сессии или она истекла | редирект на `/admin/login?next=<текущий путь>` |
| Пользователь отключён | сессии удалены → как «нет сессии» |
| Менеджер открывает `/admin/managers` или вызывает действие владельца | 404 / ошибка «Недостаточно прав» |
| Неверный логин или пароль | «Неверный логин или пароль» |
| 5 неудачных попыток за 15 минут | «Слишком много попыток. Попробуйте через 15 минут.» |
| Заявку уже взяли | «Заявку уже взял(а) <имя>», страница обновляется |
| Недопустимый статус, пустая/длинная заметка, занятый логин, короткий пароль | сообщение у поля, данные формы сохраняются |
| Заявка не найдена | «Заявка не найдена» + «К списку заявок» |
| Ошибка базы | «Не удалось сохранить. Попробуйте ещё раз.», детали — в логах Vercel |

## Тесты

Vitest + PGlite, как в этапе 1:
- `password`: хэш не равен паролю, верный пароль проходит, неверный нет, формат хэша.
- `session`: создание, поиск по токену, истечение, продление, удаление, удаление всех сессий пользователя, отключённый пользователь не проходит.
- `login`: успех, неверный пароль, несуществующий логин (та же ошибка), блокировка на 6-й попытке, логин без учёта регистра, обновление `last_login_at`.
- `requests`: фильтры по статусу/поиску/машине и счётчики, take (успех, уже взята, гонка двух take), assign, setStatus с историей, недопустимый статус, заметка (пустая, слишком длинная), resend.
- `users`: создание менеджера (занятый логин, плохой логин, короткий пароль), сброс пароля удаляет сессии, отключение удаляет сессии, владельца нельзя отключить, смена своего пароля.
- `guard`: менеджер не проходит `requireUser('owner')`.
- `telegram`: ссылка на админку есть при `SITE_URL` и отсутствует без него.

Ручная проверка в браузере (локально и на Vercel): вход, смена временного пароля, список и фильтры,
взять в работу, статус, заметка, передача, добавление/сброс/отключение менеджера, ссылка из Telegram,
вид на телефоне (375 px).

## Развёртывание
1. Миграция базы (`npm run db:migrate`) — новые таблицы и поле `assigned_to`.
2. `npm run admin:create-owner` — владелец задаёт свой логин и пароль в терминале.
3. В Vercel добавить `SITE_URL=https://velaro-three.vercel.app`, Redeploy.
