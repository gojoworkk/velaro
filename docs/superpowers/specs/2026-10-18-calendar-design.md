# Velaro — бэкенд, этап 4: календарь занятости

Дата: 2026-10-18. Статус: дизайн утверждён, ждёт ревью спецификации.

## Контекст

Этапы 1–3 работают на https://velaro-three.vercel.app: заявки, Telegram, админка с менеджерами,
автопарк/цены/скидки из админки (`/api/catalog`). Сейчас ничто не мешает принять и подтвердить две заявки
на одну машину на одни даты. Даты на сайте выбираются стандартным `<input type="date">`
(первый экран: `#booking` — поля `from`/`to`; форма: `#f-from`, `#f-to`, атрибут `data-date`).

## Решения владельца

| Вопрос | Решение |
|---|---|
| Что занимает даты | заявки со статусом «Подтверждена» и «Завершена» + ручные блокировки (ТО, ремонт, бронь по телефону…). «Новая», «В работе», «Отменена» — не занимают |
| Как клиент видит занятость | свой календарь в стиле сайта, занятые дни зачёркнуты и не выбираются |
| Вид в админке | общий календарь всех машин на месяц (строки — машины, столбцы — дни) |
| День возврата | занят: аренда 20→23 занимает 20, 21, 22, 23; следующая выдача — с 24-го |

## Правила занятости

- Период брони — `[date_from, date_to]` включительно. Два периода пересекаются, если `a.from <= b.to && b.from <= a.to`.
- Источники занятости машины: заявки `status IN ('confirmed','completed')` и `car_blocks`.
- Заявка с сайта на занятые даты отклоняется сервером (ошибка у поля `dateFrom`):
  «Эти даты уже заняты — выберите другие или другую машину.»
- Подтверждение заявки (смена статуса на `confirmed`) отклоняется при пересечении с другой занятостью этой машины:
  «Даты заняты: заявка №5, 20–23 октября» / «Даты закрыты: ТО, 20–23 октября».
  Перевод в `completed` без проверки (машина уже отъездила). Возврат из `cancelled` в `confirmed` — с проверкой.
- Ручная блокировка не может пересекаться с подтверждённой/завершённой заявкой или другой блокировкой той же машины.
  С новыми и «в работе» — может (они ещё не бронь).
- Гонка: проверка + запись выполняются в транзакции под `pg_advisory_xact_lock` по машине
  (`hashtext('car:' || car_id)`) — стандартный Postgres, переносится в РФ-облако без изменений.
- Диапазоны: дата получения не раньше сегодня (по Москве, как сейчас); период не длиннее 365 дней;
  блокировки — не дальше 2 лет вперёд.

## Сайт

### Данные
`GET /api/catalog` дополняется полем `busy` у каждой машины: `[["2026-10-20","2026-10-23"], …]` —
только будущие периоды (конец ≥ сегодня), на 13 месяцев вперёд, отсортированы, соседние/пересекающиеся
слиты. **Только даты** — без имён, телефонов, номеров заявок и причин блокировок. Кэш CDN как сейчас (~15 с).
Если каталог не загрузился — календарь работает без зачёркнутых дней; сервер всё равно проверит.

### Календарь (`public/script.js`, `public/styles.css`, `public/index.html`)
- Поля дат становятся кнопками-полями («дд.мм.гггг»/«Получение»), скрытые `input[type=hidden]` с ISO-датами
  остаются с теми же `name`, чтобы форма и `state.from/to` работали как прежде.
- По клику открывается всплывающий календарь: тёмная панель как на первом экране, месяц, стрелки ‹ ›,
  дни недели с понедельника, прошлые дни неактивны.
- Выбор диапазона: первый клик — получение, второй — возврат (если второй раньше первого — он становится новым
  получением). Подсветка выбранного диапазона и наведения. Esc/клик мимо — закрыть. Клавиатура: стрелки по дням,
  Enter — выбрать, PageUp/PageDown — месяц.
- В форме заявки: занятые дни выбранной машины зачёркнуты и не выбираются; нельзя выбрать возврат, если между
  получением и возвратом есть занятый день (такие дни тоже выглядят недоступными после первого клика).
  При смене машины, если выбранные даты стали заняты, — даты сбрасываются с подсказкой «Эти даты заняты у выбранной машины».
- На первом экране (`#booking`) машина не выбрана — дни не зачёркиваются.
- Каталог: если даты выбраны и машина в них занята — на карточке бейдж «Занята в эти даты», кнопка
  «Забронировать» неактивна; в списке машин формы такая машина помечена «— занята в эти даты» и недоступна.
- На ширине < 640 px календарь — нижний лист на всю ширину.
- Доступность: `role="dialog"`, `aria-label`, дни — кнопки с `aria-label` «20 октября, занято»/«свободно».

## Админка

### `/admin/calendar` — «Календарь» (пункт шапки для всех сотрудников)
- Шапка «‹ Октябрь 2026 ›», кнопка «Сегодня». Параметр `?month=2026-10`.
- Сетка: первая колонка — машины (видимые и скрытые, скрытые подписаны «скрыта»), далее столбцы дней месяца;
  выходные и сегодняшний день выделены.
- Полосы:
  - подтверждённая/завершённая заявка — чёрная полоса «№12 Анна», ссылка на карточку заявки;
  - блокировка — серая штриховка с причиной; клик открывает её в форме ниже с кнопкой «Открыть даты».
  Полоса, начавшаяся в прошлом месяце, обрезается по краю.
- Форма «Закрыть даты»: машина (список), с, по (стандартные поля дат — админке достаточно), причина
  (обязательна, до 100 символов, подсказки «ТО», «Ремонт», «Бронь по телефону»). Ошибки — у полей.
- Список блокировок текущего месяца под сеткой: машина, даты, причина, кто поставил, «Открыть даты».
- На телефоне сетка прокручивается по горизонтали, колонка машин закреплена.

### Карточка заявки
- Если даты заявки пересекаются с занятостью машины (кроме самой заявки) — плашка вверху
  «Даты заняты: заявка №5 (20–23 октября)» / «Даты закрыты: ТО (20–23 октября)» со ссылкой на заявку.
- Кнопка статуса «Подтверждена» при конфликте возвращает ту же ошибку (проверка на сервере).

## Данные

Новая таблица `car_blocks`:
| поле | тип |
|---|---|
| id | serial PK |
| car_id | text FK → cars |
| date_from, date_to | date |
| reason | text (1–100) |
| created_by | integer FK → users |
| created_at | timestamptz |
Индекс `(car_id, date_from)`. Индекс `requests (car_id, date_from)`.

## Код

- `lib/availability.ts` — `overlaps`, `findConflicts(db, carId, from, to, { excludeRequestId? })`,
  `busyByCar(db, today)` (для каталога, со слиянием), `withCarLock(db, carId, fn)`.
- `lib/admin/calendar.ts` — `monthGrid(db, month)`, `addBlock`, `removeBlock`, `listBlocks`.
- `lib/create-request.ts` — проверка занятости перед вставкой (под блокировкой машины).
- `lib/admin/requests.ts` — `setStatus` проверяет конфликт при переходе в `confirmed`; `getRequest` отдаёт `conflicts`.
- `lib/catalog.ts` — поле `busy`.

## Тесты

Vitest + PGlite: `overlaps` и граница дня возврата; слияние периодов; `findConflicts` (заявки разных статусов,
блокировки, исключение самой заявки); заявка с сайта на занятые даты → 400 `dateFrom`, на соседние → 201;
подтверждение с конфликтом → ошибка, без конфликта → ок, `completed` без проверки; два параллельных
подтверждения пересекающихся заявок → одно; блокировки: пересечение с подтверждённой → ошибка, с новой → ок,
удаление; каталог отдаёт только даты и только будущее; сетка месяца (обрезка по краям, порядок машин).
Ручная проверка: календарь сайта (диапазон, зачёркнутые дни, смена машины, телефон, клавиатура), каталог
«Занята в эти даты», админский календарь (полосы, ссылки, блокировки), предупреждение в карточке заявки.
